# Безопасность

## 1. Поверхность атаки

В production нет собственного SSH, Nginx, Docker или открытого порта на VPS. Публичным является только HTTPS endpoint Cloudflare Worker.

## 2. Два независимых секрета

Webhook защищается:

1. точным секретным path;
2. `crm_token` в теле MegaFon webhook.

Один секрет не заменяет другой.

## 3. Секреты

Не хранить в Git:

- `MEGAFON_CRM_TOKEN`;
- `WEBHOOK_SECRET_PATH`;
- `INTRASERVICE_LOGIN`;
- `INTRASERVICE_PASSWORD`;
- любые API tokens.

Cloudflare Secrets предназначены для API keys и auth tokens. `.dev.vars*` и `.env*` исключены из Git.

## 4. Ограничение входного запроса

Worker проверяет:

- метод `POST`;
- точный путь;
- `Content-Type: application/json`;
- размер payload не более 64 KiB;
- корректный JSON;
- `crm_token`;
- `cmd=history`;
- `type=in`;
- `status=success`;
- `duration > 10`;
- наличие `uid` и `user`.

## 5. SSRF и запись разговора

Worker не скачивает запись разговора. В IntraService передаётся только HTTPS URL, полученный из MegaFon.

## 6. Брутфорс и мусорный трафик

Поскольку endpoint находится на Cloudflare, нет собственного SSH-сервера, который нужно защищать Fail2ban. На уровне Worker запросы отбрасываются до обращения к D1/IntraService, если не пройдены базовые проверки.

Для production после измерения реального трафика рекомендуется добавить Cloudflare Rate Limiting binding на webhook route. Rate Limiting в Workers является штатным механизмом Cloudflare; он требует актуального Wrangler и имеет локальную, eventually-consistent модель счётчиков, поэтому не должен использоваться как единственный механизм защиты от дублей.

## 7. Логи

Нельзя писать в логи:

- CRM token;
- IntraService password;
- Authorization header;
- полный webhook payload.

Логируются только технические идентификаторы и типы ошибок.

## 8. Права IntraService

Учётная запись интеграции должна иметь только необходимые права:

- создание заявок в сервисе «Звонки»;
- создание заявки с нужным `CreatorId`, если это разрешено политикой вашей версии IntraService;
- назначение системного исполнителя.

Не давать интеграционной учётке права администратора без необходимости.

## 9. Персональные данные

D1 хранит технические данные, необходимые для идемпотентности и аудита. Записи разговоров не скачиваются и не дублируются в D1.

Период хранения D1 должен быть определён отдельно согласно вашей внутренней политике и применимым требованиям к персональным данным.
